# 推し検索候補の共通画像

管理者が利用条件を確認した画像だけを、認証済み利用者の推し検索候補に表示する。

## 境界

- 共通画像は `OshiCommonImage` として、個人のProfile・UserOshi・Activity画像と分離する。
- 個人画像を共通表示へ転用せず、共通画像をカードや個人画像ライブラリへコピーしない。
- 出典URLは監査メタデータとして保存するだけで、アプリから取得しない。
- 画像配信は専用経路を使い、既存の個人画像配信認可を変更しない。

## 登録・表示

- 管理者は画像、出典URL、作者・権利者、ライセンス・利用許諾、帰属表示、権利確認日時を登録する。
- 1推しにつき、有効・無効を合わせて最大10レコードとする。
- JPEG・PNG・WebP、10 MiB以下、最大辺2560px以下、総500万画素以下の既存検査を適用する。
- 検索候補は最大50件とし、候補ごとに有効画像からページ描画時に1枚を選ぶ。同じ描画中は変更しない。
- 画像がない場合はプレースホルダーを表示し、表示画像に対応する帰属とライセンスを併記する。

## 認可・失効

- 配信時にログイン、画像の有効状態、attachment、Oshiの現行可視性を毎回確認する。
- レスポンスは `private, no-store` とし、無効化・削除後の新規要求は404にする。
- 既に端末へ描画された画素を無効化によって回収できるとは扱わない。

## Oshi統合

- 統合元の画像と権利情報を統合先へ移す。
- 合計が10件を超える場合は画像を自動削除せず、統合全体を中止する。
- ファイル、attachment、出典、ライセンス、帰属情報を保持する。

## 対象外

- 実在画像の収集・権利判断・本番投入
- 初期の名前・別名・所属データ整備
- AWS・production DB・本番ストレージの変更
- 外部URLからの画像取得

外部のテーブル定義、ER図、推し検索ワイヤーフレーム、画面遷移図は、原本のバックアップを保持した別工程で同期する。
