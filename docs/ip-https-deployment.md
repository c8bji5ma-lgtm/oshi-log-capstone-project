# IP アドレスでの HTTPS 公開

本番アプリは、EC2 ホスト上の TLS 終端リバースプロキシからのみアクセスさせます。
Rails / Thruster のポートは `127.0.0.1` に限定し、DB ポートとストレージを外部公開しません。

## Rails の必須設定

- 実行時に `PUBLIC_APP_HOST` へ公開 IPv4 アドレスを指定する。
- 未指定または IPv4 アドレス以外の場合、本番アプリは起動しない。
- 秘密なしのイメージビルドでは、Dockerfile のビルド手順に限って
  `PUBLIC_APP_HOST=127.0.0.1` を明示する。本番実行時の未指定を許可する例外は設けない。
- TLS 終端後のリクエストとして扱い、HTTPS リダイレクト、HSTS、Secure Cookie を有効にする。
- 許可する Host ヘッダーとメール内 URL は `PUBLIC_APP_HOST` に限定する。

## リバースプロキシの境界

- 80 番は証明書検証と HTTPS へのリダイレクトだけに使用する。
- 443 番から `127.0.0.1:3000` へ転送し、`Host`、`X-Forwarded-Proto=https`、
  `X-Forwarded-For` をプロキシ側で設定する。クライアントが送った転送ヘッダーをそのまま信用しない。
- `client_max_body_size` は、アプリの 10 MiB 制限に multipart の余裕を加えた 12 MiB とする。
- `storage/` を静的配信しない。個人画像と共通画像は、既存の Rails 認可エンドポイントだけを通す。
- Rails / Thruster の 3000 番、PostgreSQL の 5432 番は Security Group へ公開しない。

証明書は公開 IPv4 アドレスを SAN に含むものを使用します。証明書・ACME の秘密鍵は
EC2 上で権限を制限して保管し、Git、環境イメージ、チャット、ログへ出力しません。

## 公開前の確認

1. HTTP が同じ IP の HTTPS へ転送される。
2. 許可した IP 以外の Host ヘッダーが拒否される。
3. セッション Cookie に `Secure` が付き、ログイン、CSRF、Turbo 遷移が動作する。
4. `/up` が内部とリバースプロキシ経由の双方で成功する。
5. 10 MiB 境界のアップロードがプロキシで先に拒否されない。
6. 個人画像は本人だけが取得でき、他ユーザーと未認証アクセスは拒否される。
7. `storage/` の直接取得ができず、カードのプレビューと PNG 保存が一致する。
8. ホスト上では 80 / 443 だけが外部待受で、3000 / 5432 は外部待受しない。
